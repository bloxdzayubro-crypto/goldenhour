# Golden Hour — Bloxd シェーダーパック (apiVersion 5)

bloxd.io の公式シェーダーパック機能(WebGPU 専用)用のパック。立体的で、リアルで、光に色がある見た目にする。

> **状態(2026-11-22): 公式コンパイラの検証は、通っている(エラーなし、6 種類)。ゲーム内の見た目は、まだ見ていない。**

## 入れ方(あなたの操作)
1. WebGPU が使える Chrome 系ブラウザで bloxd.io を開く。
2. 設定 → **Shader Pack** を開く。
3. `GoldenHour.zip` をドロップする。検証が通ると「ready」、だめなら、行番号つきのエラーが出る。
4. 画面の案内に従い、ページを再読み込みする。
5. シェーダーパックを許可しているゲームでだけ効く。

## 中身
- `pack/pack.json` … 名前と apiVersion(5)。
- `pack/golden_hour.wgsl` … 本体(約 21 KB)。先頭の「調整用の値」(立体感・光と色・質感・空気と仕上げ・水)で、強さを変えられる。
- `GoldenHour.zip` … 上の 2 つを、ルート直下に入れた配布用 zip。**wgsl を直したら、検証してから、zip を作り直す。**

## 揺れが効くゲーム(重要)
このクライアントは、`shaderPackPolicy` が書かれていないゲームを **strict(厳格)として扱う**(クライアントのコードで確認)。strict では、エンジンが頂点を動かす処理(葉・植物の揺れ)と、`discard`(葉の黒い部分の透明化)を禁止する。シェーダーパックの方針を `allow` にしているのは、次のゲームだけ(クライアントの設定から、2026-11-22 時点の読み取り。表示名は、おおよそ):
Test Mode / Bloxd Hop / Fishing / Test Gym / Evil Tower / Plots(建築)/ Doodle Cube / Rocket Obby / Tsunami Steal Brainrots / Work at a Restaurant / Dress Up。
**普通のゲーム(サバイバルなど)では、揺れも葉の透明化も、仕組み上できない。** 凹凸・影・光の色・水・落ち葉は、strict でも効く。

- **切ったもの(重い処理を、定数の分岐に閉じ込めて、実行時に走らないようにした):** 空中の落ち葉・雪(視線に沿った繰り返し)/ 水の波紋・水しぶき(3×3 区画の繰り返し)/ ブロックの凹凸(微分 + 画像 5 回読み)/ 光の筋(影を 5 回読む)/ 雲の影・木漏れ日・水面の雲・細かいさざ波(ノイズ計算)/ 草の風の明暗。

## 2026-11-22 の調整その 9

## 2026-11-22 の調整その 8(ユーザーが共有してくれた別のシェーダーを参考に)
- **空中を舞い落ちる葉を作り直した(strict でも効く):** 前の「木の板を切り離して落とす」方式は、やめた(木に穴が開くため)。かわりに、**ライティングのフックの中で、視線に沿って空中の区画を調べ、回る正方形の葉を、手前に重ねて描く**。葉のブロックを見ているとき、または木の下だけに出る(`LEAF_BITS` / `LEAF_BITS_DENSITY` / `LEAF_BITS_SIZE` / `LEAF_BITS_CELL` / `LEAF_BITS_FALL`)。**空(スカイボックス)の前には描けない**(空は、フックの対象外)ので、葉は、地面・木・建物を背景にしたときだけ見える。仕組みの参考にしたのは、共有された zip の落ち葉の描き方で、コードは、自分で書き直した。
- **木漏れ日:** 木の下の影に、ゆっくり動く光の斑点(`DAPPLE`)。
- **草の上を渡る風の明暗:** 日向の草の上を、明るい波が走る(`GUST`)。頂点を動かさないので、strict でも、風の動きが見える。
- 葉・植物の「頂点の揺れ」は、従来どおり、strict でないゲームだけ。

## 2026-11-22 の調整その 7

## 2026-11-22 の調整その 6
- **地面の落ち葉は、削除。** かわりに、**空中を舞い落ちる葉**(非 strict のゲームのみ): 木の下向きの面(正方形の板)の一部(`LEAF_FALL` = 10%)が、元の場所から外れて、回りながら(`LEAF_FALL_SPIN`)ゆらゆら落ち、小さくなって消え、元の場所に戻る。落ちている間、元の場所の板は、一時的に無くなる(木に、ときどき小さな穴ができる)。
- **プレイヤー・mob(モデル)の見た目:** テクスチャの凹凸・くぼみ・強い影・強いコントラストを使わないようにして、ごちゃつきと暗さを減らした。自分の体に落ちる影(自己影)も使わない。
- **地面に落ちるプレイヤー・mob の影を復活**(`PLAYER_SHADOW` = 0.55。0.0 で消える、1.0 で標準どおり)。ブロックの影は、そのまま。
- **宝石感:** 鉱石の色の粒が、ほんのり自分で光る(`ORE_GLOW`)。アイテム(手持ち・落ちている・飛んでいる)の、色のはっきりした部分(ダイヤの水色など)にも、輝きと発光を付けた。**テクスチャの色から見つけるので、元のテクスチャでも、自作パックでも、効く。**
- 合わせて使うテクスチャパック(アイテムのモデルも対応): `../texture-pack/`。

## 2026-11-22 の調整その 5(地面の落ち葉は、その 6 で削除)

## 2026-11-22 の調整その 3(ユーザーの感想を受けて)
- **揺れが弱い** → 葉っぱ(`LEAF_SWAY` 0.06→0.14)、草・花など(`PLANT_SWAY` 0.10→0.28)を大きく・速く。植物は、上ほど大きく揺れる。**揺れは、strict でないゲームだけ。**

- **日向と影の差を強めた**(`SUN_BOOST`)。陽ざしの強さが出る。
- **水中** → 水の中から水面を見上げると、真上は空が見える窓、斜めは青緑の鏡(全反射)になる。水中の底に光の網目(コースティクス)、青緑の色味、霧に合わせた光の筋(`UNDERWATER_FX`)。水中かどうかは、エンジンの霧の色・濃さから推定している(推定なので、外れる場面があるかもしれない)。

## 2026-11-22 の調整その 2(ユーザーの感想を受けて)
- 水が暗い → 水の色を明るく(`WATER_SHALLOW` / `WATER_DEEP` / `WATER_BRIGHT`)。吸収を弱め、透明度も上げた。
- ブロックの境界線がくっきり → 縁の面取り・溝を既定で切った(`BEVEL` / `EDGE_DARK` = 0.0)。もう 1 つの原因は、凹凸の計算でタイルの端が反対側にまわり込み、境界に偽の段差ができていたこと。端は反対側を見ないようにした。
- 葉っぱ → 光り方・色のばらつきを控えめに。**黒い(透明な)部分は透明に**(`LEAF_CUTOUT`)。
- **揺れ:** 葉っぱ(`LEAF_SWAY`)に加えて、草・花・作物などの平面の植物も揺れる(`PLANT_SWAY`)。根もとは動かさない(モデルの座標がある場合)。
- **鉱石:** 色がはっきりした粒・とても明るい粒(ダイヤ・エメラルド・金・ラピスなど)を、光で浮き上がらせ(`ORE_RAISE`)、宝石のように輝かせる(`ORE_SHINE`)。実際の形を飛び出させることは、仕組み上できない(下記)。

- **できないこと:** 鉱石などの「本物の形の飛び出し」(頂点を細かく分けられず、テクスチャの 1 粒ごとに形を変えられない)。

## 何をしているか
- **凹凸:** テクスチャの明暗から表面の凹凸(法線)を作り、太陽の当たり方に反映する。くぼみは暗く、出っ張りは明るく。レンガの目地・鉱石の粒・石の割れ目に陰影が出る。遠くでは自動で弱める(ちらつき防止)。
- **影・光の筋:** 太陽・月の影(`bloxdShadow`)を効かせ、日向は暖色・影は寒色。木漏れ日や洞窟の入口に、空気中の光の筋(`bloxdAirShadow`)。雲の影が地面を流れる。
- **光の色:**
  - 光る素材(`flags.emissive`)は、素材そのものの色で光る。クリスタル = 緑、溶岩 = 赤橙、ネオン = その色。明るい部分ほど強く、ゆっくり脈打つ。
  - 光源が出す光の色(エンジンの `blockLight` / `heldLight`)を濃くして、周りの素材に「色つきの光だまり」を落とす。ゆらぎ付き。
- **質感:** 3 段の色むら、岩のつや、砂のきらめき、葉っぱの透けとつや、斜めの面の空の映り込み。
- **空気・仕上げ:** 太陽方向のかすみ。明るい部分をなだらかに丸め、彩度・コントラストを調整。
- **水:** 波長ごとに吸収が違う色、4 つの波のさざ波、空の反射、太陽のきらめき、岸の泡、光の筋。
- **モデル**(プレイヤー・アイテム・mob): 地形と同じ光の仕上げ。
- 頂点移動・`discard` なし(strict なゲームでも有効)。

## 確認したこと / していないこと
- **確認した:** 公式コンパイラ(apiVersion 5)の検証でエラーなし。strict/許可 × 地形/液体/モデルの 6 種類の完成形(公式ヘッダ込み)を、実際の WebGPU でコンパイル成功。
- **確認していない:** ゲーム内の見た目(ゲームには入っていない)。エンジンの光の強さの単位は、ヘッダのコメントからおおよそ分かるが、実際の明るさは見ていない。
- **見た目が合わないとき:** 強すぎる・弱すぎるときは、先頭の「調整用の値」を変える。例: 凹凸 `RELIEF_DEPTH` / `CAVITY`、光だまり `SPILL`、発光 `GLOW_*`、光の筋 `SHAFT`、全体の `SATURATION` / `CONTRAST`。
