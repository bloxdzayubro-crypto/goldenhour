# Golden Hour テクスチャパック (シェーダー「Golden Hour」用)

bloxd.io の「今の」標準テクスチャ・モデルを元に、絵柄を保ったまま、リアルで精細にしたテクスチャパック。シェーダー `../shader-pack/` と組み合わせると、いちばん映える。

> **状態(2026-11-22): 画像・モデルの生成と、3D ビューアでの確認まで。ゲームに入れての確認は、まだ。**
> 確認画像: `preview_blocks_before_after.png`(ブロック、左 = 元、右 = 加工後)、`preview_sky.png`(空)。

## 入れ方(あなたの操作)
1. bloxd.io の設定 → テクスチャパックを開く。
2. カスタムのテクスチャパックのドロップ欄に、**`GoldenHour-Textures-64-All` フォルダをドロップ**する(中の `textures` ではなく、その 1 つ上のフォルダ)。
3. 再読み込みして、確認する。外すときは、設定で、標準(Default 2)に戻す。
- **全部入り(約 54 MB)**。重い・読み込めないときは、`GoldenHour-Textures-64-Blocks`(ブロック・植物の素材だけ、約 7 MB)を試す。エンジンが、どこまで大きなパックを受け付けるかは、確かめていない。

## `GoldenHour-Textures-64-All` の中身(全部まとめてある)
| 中身 | 数 | 内容 |

| `textures/` ブロック・植物 | 826 枚 | 公式 `default2` 640 枚 + ゲームに組み込まれた、`default2` に無い素材 186 枚(ドアの上下・トラップドア・はしご・チェストの上面・機械の上面・苗・作物・テラコッタなど)。64×64 |
| `textures/` **アイテムのアイコン** | 1588 枚 | 剣・ツルハシ・斧・食べ物(りんご・コーン・パンなど)・花火(rocket)・防具・矢・道具・効果のアイコン。10×10 のドット絵を、**輪郭を保ったまま、面取りの陰影と素材の質感で立体にした** 80×80 |
| `textures/` **着る防具** | 23 枚 | 着たときの防具(`*_armour_2` など)の展開図。**元と同じ大きさ(64×64 など)** |
| `textures/` mob・プレイヤー・マント・着せ替えの皮 | 355 枚 | **ぼかさずに**(ぼやけを直した)、毛並み・陰影を足した。256×256 以上 |
| `models/` | 2114 個 | アイテム・家具・ブロックのモデル(画像を差し替え、色見本のものは、UV と画像を作り直して模様つき) |

## 何が、どう変わるか
**アイテムのアイコン(作り直した。丸めない版):** 持ち物欄・ホットバー・落ちたアイテムなどの 2D の絵は、10×10 の小さなドット絵(黒い縁取りつき)で、名前(`diamond_sword`・`apple`・`corn`・`rocket` など)で上書きされる。
- 前の版は、輪郭を丸めて全体をふくらませたため、粘土のように見えて、リアルさがなかった(指摘のとおり)。**今回は、輪郭を、ドットの形のまま保ち**(丸めない)、次の表現にした: 縁の面取りの明暗(左上の光)/ 素材ごとの質感(金属 = 研いだ筋と鋭い光、金 = ぎらつき、宝石 = きらめく光の点、木 = 木目、食べ物 = 弱いつや)/ 色の塊の内側のなめらかさ / 右下の薄い影。
- **限界:** 元が 10×10 の絵なので、**写真のようなリアルさは、出せない**。形は、元のままで、陰影と質感を足した、という作り。確認画像: `preview_icons_before_after.png`(左 = 元、右 = 今回)。

**着る防具(直した):** 以前は、`armour_2` の名前の条件から外れて、一度も変わっていなかった。その後、変えたときに、**大きさを 64×64 から 256×256 にしたのが、不具合(変な色が変な形で貼られる)の原因と考えられる**: ゲームは、防具専用のアトラスを、この画像から**自動で組み立てる**ので、大きさが違うと、左上の一部分だけが拡大されて貼られる。**今回は、元と同じ大きさのまま**にして、ドットの形と配置は、そのまま、縁の面取りと明暗だけを足し、**平均の色を元に合わせた**(1% 以内)。確認画像: `preview_armour_before_after.png`。

**植物(コーン・小麦・花・苗など):** 形(小麦の隙間・葉の切れ込み)を保ちながら、繊維・葉脈・小さな丸み・弱いつやを足す専用の描き方にした。

**mob・プレイヤー・マント・着せ替えの皮:** 前の版は、角を丸める処理が「ぼやけ」の原因だった。**ぼかしをやめ**、ドットの輪郭を保ったまま、毛並みの筋・粒・陰影・くぼみの暗さを足した。元が「ブロック状のドット絵」の mob なので、リアルな別デザインへの描き直し(造形そのものの変更)は、自動では、できない。

**ブロック(はっきり変わる):** 粒・ひび割れ・木目・草の筋に加えて、**画像そのものに、立体感を焼き込んだ**(左上からの光の陰影と、くぼみの暗がり)。レンガは目地がへこみ、羊毛は織り目、コンクリートは気孔、テラコッタは光沢。鉱石は浮き上がって影が落ちる(`preview_blocks_before_after.png`)。**シェーダーが効かないゲームでも、この立体感は、出る。**

**変化を、強くした(第 2 版):** 「違いが小さくて気づきにくい」との指摘を受けて、アイコンは、面取りの深さ・明暗の幅・つや・素材の模様・彩度とコントラストを、およそ 1.5〜2 倍にした。着る防具は、面の明暗・研いだ筋・つやを強めた(平均の色は元に合わせたまま)。手に持つモデルも、このアイコンから作り直した。

**ドア・トラップドア(専用の描き方に変更):** 元は 8×8 の穴あきの板で、板の模様が無かった。**木目(ゆがんだ年輪の筋)・板の継ぎ目・節・釘・穴の縁のくぼみの影・面取り**を足した(`tools/gen_doors.py`、36 枚)。穴の位置と色の塊の形は保ち、平均の色は元に合わせた。鉄のトラップドアは、研いだ筋・リベット・強い反射。

**手に持ったアイテム(剣・ツルハシ・食べ物など)を、新しいアイコンの見た目に:** 手に持つモデルは、8×8 ほどの格子に並んだ小さな立方体でできている。そこで、**新しいアイコン(面取り・つや・影つき)の画像を、モデルの前面・背面にそのまま貼り**、側面には、縁のドットの色を貼った(`uvx.mjs --icons`)。**841 個**(アイコンのあるアイテム)。形は変わらない(面の数・外形を、元と突き合わせて確認)。3D ビューア(three.js)では、リンゴ・ツルハシ・胸当て・コーン・ダイヤの剣で、アイコンと同じ陰影になることを確認した。**ゲーム内の手持ち表示は、ゲームに入って確かめていない**(ゲーム側の照明・シェーダーで、見え方は少し変わる)。アイコンの外側の黒い縁取りも貼られるので、手に持つと、黒い縁がつく。

**アイテム・防具の 3D モデル(手に持ったとき・落ちたとき):** アイコンのないもの(色見本のモデル)は、各面の UV を、見本の 1 マス全体を指すように広げ(`tools/uvx/uvx.mjs`)、1 マスを、色に合わせた模様(金属の筋・宝石の面取り・木目)に作り直した。**1372 個**。形(三角形の数・外形)は、元と同じ(2114 個全部を、元と突き合わせて確認)。ただし、形は、ブロック状のままで、模様は、小さな面の上の細かな模様。

## UI(画面の部品): `css/golden_hour_ui.css`
**重要な発見(第 3 版までが、ゲームで効かなかった原因):** ゲームは、テクスチャパックの CSS を、そのまま使わず、**厳しい制限つきで取り込む**(クライアントのコードから確認)。
- 取り込めるのは、**`.クラス名 { プロパティ: 値; }` の形だけ**。 `.A .B { }` は、**最後の `.B` だけ**になる(文脈は消える)。 `:hover`・`@media`・`:root`・疑似要素(`:after`)は、使えない。 クラス名は、英字と数字だけ。 各宣言の最後に `;` が要る。
- 使えるプロパティは、背景・枠・影・色・フォント・余白・サイズなどの一覧だけ。 **`content`・`--変数`・`inset`・`object-fit` は不可。**
- 値に、`$ & ; < = > ? @ [ \ ] ^ { | } ~` が入ると、その宣言は捨てられる。 **このため、base64 の画像(`;` と `=` を含む)は使えず、顔の画像は、`%XX` だけで書いた `data:image/png,…` の形にした。**
- `url()` は、`data:` などだけ(他のサイトの画像は不可)。
→ 第 3 版までの CSS は、`.A .B`・`:after`・`content`・base64 を多用していたので、**ほとんどが捨てられていた**。第 4 版で、この制限の中で効く形に作り直した。`ui-src/pack_css_check.py` が、ゲームの取り込みを再現して、効く規則だけを書き出す。

**第 4 版の中身(ゲームの取り込みを再現して確認済み):**
- **自動の着せ替え(約 500 クラス):** ゲームの CSS(48 ファイル)から、クラス名で終わる規則を拾い、青系の色(背景・枠・影)を、金・茶色系に置き換えた(`ui-src/gen_ui_theme2.py`)。 同じクラスが、場所によって違う色を持つ場合と、「Body」「Header」のような、どこにでもある名前は、にじむので、除いた。 ボタンの色は、色の変数(使えない)で決まるので、**変えられない**(元の色のまま)。
- **手書き(`ui-src/hand_rules.css`):** ホットバー・スロット(明るい革・真鍮色の地に、金の縁と、くぼみの陰影 = 黒縁のアイテムが見やすい)・選択中(明るい金)・HP バー・シールドバー・持ち物欄・ホバーの説明・クラフトの検索欄・チャット。
- **顔:** `.LogoLoader` の背景に、添付の顔を置いた(ロゴの顔・ロード中の顔)。 `.LogoLoaderInner`(元のロゴ)は、透明にした。 **ホームの自分のアバター(`.ProfilePicture`)は、変えていない**: 友達・他のプレイヤーのアバターも、同じクラスで、全部が、あなたの顔になってしまうため。
- **第 5 版(青が残る件の修正):** 自動の着せ替えを、500 → 約 625 クラスに増やした(色が文脈ごとに違うクラスは、いちばん多い色を採る。`rgba(…, var(--x))`・`hsl()` の色も、変換できるようにした)。 ボタン(`.BlueButton`・`.DarkBlueButton`)の本体を金・茶色にし、ボタンの上下の縁は、白・黒の半透明にして、どの色のボタンでも、立体感が出るようにした。 ロードのリング(`.LogoLoaderLoadingBar`)は金。 **実際の bloxd.io のホーム・設定(全タブ)・ストアを、1 要素ずつ調べて(青系の色を持つ要素の検出)、ホームと設定には、青が残っていないことを確認した。**
- **残る青(CSS では、変えられないもの):** 色の変数で決まる色(ボタンにマウスを乗せたときの色など)、アイテムごとにゲームが決める色(ストアの背景・レア度の枠)、サーバーが送る名前の色、Discord のロゴ、チェックボックス(`rc-checkbox` のようにハイフンを含むクラス名は、パックでは使えない)、`:hover` など状態別の色。
- **確認:** 実際の bloxd.io のホームに、取り込み後の CSS を重ねて、茶色・金の配色と、顔の差し替えを確認した。 **ゲームの世界の中は、未確認。**
- **限界:** `:after` の光沢・文字の縁取りの擬似要素・状態(hover)ごとの色・ボタンの色は、できない。 `.Selected` は、どこでも使われる名前なので、選択中の項目が、全部、金色になる。

## 最終調整(第 6 版)
- **ワールド参加時などのロード画面の顔は、円形に「切り抜いた」:** 進捗つきのロード(`.LogoLoaderIsProgressBar`)の背景に顔を置き、`border-radius: 50%` で円に切り抜いた(顔を小さくして収めるのではなく、円いっぱいに、顔を敷く)。 ほかの場所のロゴ・ロードの顔は、四角のまま。実際のホームの画面に、同じ部品を置いて、円の切り抜けと、ほかが四角のままなのを確認した。
- **手に持ったアイテムの「背面」が左右反転していた不具合を直した(ナイトの剣など):** 同じブロックの前面と背面は、同じドットの色にするべきなのに、背面だけ、反対側のドットを貼っていた。ナイトの剣では、背面の白い刃が、黒く潰れていた。 直したあと、アイコンと、元の色見本の色が合わない面の割合の中央値は、ほぼ 0 になった。
- **品質チェックを追加(他にも同じ問題が無いか、全モデルを確認):** 各モデルの面ごとに、元の色見本の色と、貼ったアイコンの色を比べ、**合わない面が 12% を超えるモデルは、アイコンを貼らず、模様つきの色見本のまま**にした(風船・ペイントボールの銃・ウィップなど約 80 個。形が、アイコンの絵と、そもそも合わない)。 貼ったのは、約 760 個。
- **参考パックの素材の追加(88 枚)は、取り消した:** チェスト・ネオンなど、見た目が合わなかったため、元に戻した。
- **「テクスチャパックを読み込んだときに出るアイコン」:** ゲームのコード(クライアント)を調べたが、パックのアイコンを指定する仕組みは、見つからなかった(パックのフォルダには、`textures` `models` `skyBoxes` `css` `animations` だけが許される)。 何もしていない。
- **軽量版 `GoldenHour-Textures-Lite`:** ブロック 32×32(本編の半分)・アイコン 40×40・皮 128・モデルの画像 32。 実際のバイト数で、本編の約 43 MB が、約 20 MB(zip で約 19 MB)。 ブロックの画像が、1/4 の面積になるので、メモリの使用も、減る。 モデルの形(形状データ)は、同じなので、モデルの分(約 9 MB)は、減らせていない。 **ゲームの速さの差は、測っていない。**
- **確認の範囲:** ブラウザでの見た目の確認(3D ビューア・ホームの画面)まで。 ゲームの世界の中は、未確認。

## 空(スカイボックス)
- 昼・夕方・朝方・夜・曇りの 5 種類(`GoldenHour-Sky-*`)。全部入りには、`default` = 昼、`starry` = 夜、`gloomy` = 曇りを入れてある。切り替えは、`.\switch_sky.ps1 Sunset`(Day / Sunset / Dawn / Night / Overcast)→ ゲームで、フォルダを、もう一度ドロップ。
- **効くのは、ゲームが、その名前の空を使っているときだけ。** クライアントの標準設定は `skyBox: "default"` だが、**ゲームごとの空は、サーバー側で指定される**。昼夜サイクルのあるゲームなどは、プログラムで描く「earth」の空を使うので、**画像の空では、置き換えられない**(仕組み上の限界。そのゲームでは、ゲーム自身の昼夜が、そのまま動く)。「何を追加しても空が変わらなかった」のは、これが、いちばん疑わしい。
- 夕方・朝方・夜の空にしても、地面の明るさ(光)は、昼のまま。

## 上書きしない(不具合を避けるため)
- **ブロック用とアイテム用で、同じ名前のモデル 110 個**(ドア・ベッド・旗・エンチャントテーブル・トロフィーなど)。パックは、名前で上書きするので、片方の形で、もう片方を壊してしまう(前の版で、ドアが黒い枠に、ベッドが黒い塊になった原因)。ゲームの組み込みのまま。
- 生き物(mob・プレイヤー本体)の**モデル**。パックでは、差し替えられない。

## 作り方(`tools/`)
入力は、全部、「今のゲームが実際に使っているもの」(古い GitHub の `default` フォルダは、使っていない)。
- `build_all.py`: ブロックの素材・皮・画像を持つモデル。 `uvx/uvx.mjs`: 色見本のモデルの UV と画像(Node。`cd tools/uvx; npm install --ignore-scripts` が要る)。 `gen_sky.py`: 空。 `gen_textures.py` / `gen_items.py`: 共通の処理。
- 元のデータ(公式の `default2`、ゲームに組み込まれた画像・モデル、モデルの目録)は、このフォルダには置いていない。取得の手順は、`build_all.py` の先頭に書いてある。

## 注意
- 元の素材は、公式の標準テクスチャ・モデル。**自分で使うためのもの**として作った。公開・再配布は、しないこと。
- ゲームの更新で、モデル・テクスチャが変わると、食い違う可能性がある。おかしくなったら、最新から、作り直す。
